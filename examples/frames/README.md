# frames

One abstract dataframe model, `Frame`, with two libraries behind it that disagree about missing values. The spec is frames.spec.

- **The model.** A Frame has float columns. Its fields are its column names, its rows of `option<f64>` cells and its row count. A missing cell is `none`; a NaN that a library keeps as a value is `some(NaN)`.
- **Invariant-driven generation.** The model's invariants (`distinct(columns)`, rectangular rows, `nrows == len(rows)`) shape the generated frames, so none is rejected.
- **Raises on models.** `select` must raise ColumnNotFound, a condition computed from the frame's observed columns.
- **fresh and unspecified sharing.** `dropna` and `fillna` must return new objects, but may share memory with their input.

## Bindings

**pandas.** The concretizer builds a float64 DataFrame.
- none and some(NaN) both become NaN.
- The index carries the row count, so a frame can have rows and no columns.
- The observers read every NaN as none, because pandas has no other null for floats.

**polars.** The concretizer builds Float64 columns.
- none becomes null, and some(NaN) stays a NaN value.
- A frame with rows and no columns is built with `pl.DataFrame(height=n)`. A polars without that parameter cannot hold one, and the concretizer raises Unrepresentable, so the example is skipped.
- The observers read null as none and NaN as some(NaN).

**Both.** The observers refuse a column whose dtype is not float64 by raising `spectest.NotAValue`; they do not convert it. `accepts` refuses anything but a DataFrame of the library. On a result, either makes the function's `#type` item fail. spectest reads every concretized frame back and reports a binding error if it differs from the generated fields, so a binding bug is reported rather than testing a different input. The pandas binding is `lossy=True` (some(NaN) reads back as none), so it is exempt, and its counterexamples show the frame as built next to the generated one.

## Conformances

| Conformance | Library | dropna | fillna | select |
| --- | --- | --- | --- | --- |
| `test_pandas` | pandas | `df.dropna(how=how)`; an omitted `how` is left to pandas' default | `df.fillna(value)` | `df[names]`, with KeyError mapped to ColumnNotFound |
| `test_polars` | polars | `drop_nulls()` for how="any"; for how="all", a filter keeping rows with any non-null cell | `fill_null(value)` | `df.select(names)`, with ColumnNotFoundError mapped to ColumnNotFound |
| `test_seeded_bugs` | polars | ignores `how` | `fill_nan(value).fill_null(value)` | not bound |
| `test_seeded_fresh` | polars | returns its input when no row is dropped | not bound | not bound |

## Running it

```
uv run pytest examples/frames                                              # about 35 s
uv run pytest examples/frames --spectest-report=examples/frames/REPORT.md  # same, writes the report
uv run pytest examples/frames/explore_frames.py                            # the weakness demos
uv run pytest examples/frames -k "test_pandas or test_polars" \
    --spectest-max-examples=2000 --spectest-seed=7                         # deep run, about 15 min
```

## What to expect

The default run gives 85 passed and 6 xfailed, exit 0.

| Conformance | Items | Outcome |
| --- | ---: | --- |
| `test_pandas` | 27 | All pass, including the explicit examples of pattern names. |
| `test_polars` | 27 | 24 pass. `select.rows` is an expected failure: `df.select([])` on a frame with one row and no columns returns a 0 x 0 frame (FINDINGS.md 1). So are `select#2` and `select.columns`, on the explicit example names = ["*"]: polars reads the name as a pattern and returns every column instead of raising ColumnNotFound (FINDINGS.md 2). |
| `test_seeded_bugs` | 18 | Expected failures `dropna.rows` (how="all" keeps a row without cells) and `fillna.rows` (a NaN value is overwritten). The other 16 pass. |
| `test_seeded_fresh` | 9 | Expected failure `dropna.fresh` (the empty frame comes back as the same object). The other 8 pass. |

The ten plain tests check each finding and counterexample with pandas and polars directly. spectest's generator almost never draws names such as `*` and `^...$`, so test_frames.py gives both libraries' conformances two such names as explicit examples (`examples=PATTERN_NAMES`), judged on every select item before the search. `test_polars_select_reads_names_as_patterns` checks the same behaviour directly (FINDINGS.md 2).

`explore_frames.py` ends with 3 failures, by design: `fillna#type` (`test_dtype_change`), and `select#2` and `select.columns` (`test_select_skips_missing`).

## Weaknesses this case shows

- **A result that is not a valid Frame was charged to the spec** (fixed). In `test_dtype_change`, `fillna` returns object columns. `fillna#type` used to pass, and every clause that read the result was a SPEC ERROR, "the spec's or the binding's fault". The observers now raise `NotAValue`, and `fillna#type` fails.
- **Counterexamples showed the generated input** (fixed). spectest did not check that the concretizer built what was asked, so a concretizer bug (polars renaming "" to "column_0") or a lossy one (pandas some(NaN)) was invisible. It now reads every built frame back: a mismatch is a binding error, and a lossy binding's counterexamples show the input as built.
- **Shrinking stalled on dependent fields** (fixed). Rows are drawn to the column count, so the seeded counterexamples kept 3 and 4 columns where 0 or 1 fail. spectest's pass after Hypothesis's shrinking now removes a column with its cell in every row, and the counterexamples have 0 and 1 columns.
- **Rare inputs could not be added by hand** (fixed). `conformance(examples=...)` now lists inputs known to be tricky (names `*` and `^b.*$`), judged before the search; before, they were reached only by chance. The counterexample store is still local and git-ignored.
- **expect_fail names a clause, not a cause.** Once `select.rows` is expected to fail, any other failure of it is hidden.
- **Spec errors were not minimized** (fixed). They are now shrunk like failures and reported once per kind of error.
- **Some items can't be picked with `-k`.** `pytest -k` cannot select items whose names contain `#`; use `--spectest-clause='select#*'` or the node ID instead.
